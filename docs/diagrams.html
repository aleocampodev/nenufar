Core rule: No direct "Buyer → Bot" arrow. The buyer journey is 100% web; the Telegram push is a one-way notification to Shirley. The bot webhook strictly rejects any chat_id != TELEGRAM_ADMIN_CHAT_ID.

Order Lifecycle State Machine

Matches exact Payload TypeScript enum: processing, completed, cancelled, refunded.

stateDiagram-v2
  [*] --> Cart: item added
  Cart --> Processing: submitOrderAction()\n(payload.create)
  Processing --> Processing: Telegram send fails\n(order safely saved)
  Processing --> Completed: Shirley verifies payment\n(payload.update)
  Processing --> Cancelled: Customer cancels / out of stock
  Completed --> Refunded: Warranty / return
  Completed --> [*]
  Cancelled --> [*]
  Refunded --> [*]

  note right of Processing
    status: 'processing'
    Telegram HTML sent
    Idempotent: sha256
  end note

Bot Conversation State (Claude Agent SDK)

Resilient execution loop at /telegram/webhook with turn bounds and fallback error handling.

stateDiagram-v2
  [*] --> Idle: Telegram webhook idle
  Idle --> Auth: POST /telegram/webhook
  Auth --> Rejected: chat_id != ADMIN\n-> 200 ignore
  Rejected --> [*]
  Auth --> Dedup: chat_id == ADMIN
  Dedup --> Ignored: update_id seen\n-> 200 OK
  Ignored --> [*]
  Dedup --> Thinking: Agent SDK query()
  Thinking --> ToolCall: LLM chooses tool
  ToolCall --> ToolResult: payload.find/update\n(Local API)
  ToolResult --> Thinking: feed result to LLM\n(max 4 rounds)
  Thinking --> Reply: final text response
  Reply --> Sent: sendTelegramReply()
  Sent --> [*]
  Thinking --> Error: Groq timeout / 429
  Error --> Sent: fallback reply\n"try again 💜"
Why two decoupled state machines? Order state is persistent and business-critical in PostgreSQL. Bot conversation state is ephemeral (in-memory LRU Set for deduplication) — if the bot encounters a transient error, the order remains completely safe in the database.

⚡ 1. Sequence Diagram · Buyer Order ($0 Transaction Cost)

Buyer never touches Telegram or LLMs. Form submission is validated and idempotent.

sequenceDiagram
  autonumber
  actor Buyer as 🛍 Buyer (browser)
  participant Next as Next.js App Router
  participant Action as submitOrderAction
  participant DB as PostgreSQL (Payload Local API)
  participant TG as Telegram Bot API (Channel)

  Buyer->>Next: POST /pedidos/enviar {name, phone, cart, consent}
  Next->>Action: server action (validate Ley 1581)
  Action->>Action: idempotency check sha256(cart+phone)
  alt duplicate submission
    Action-->>Buyer: 409 already submitted
  else new order
    Action->>DB: payload.create('orders', {items, amount, status:'processing'})
    DB-->>Action: order #1042 created
    Action->>TG: POST sendMessage {chat_id: CHANNEL_ID, parse_mode:HTML}
    alt TG send ok
      TG-->>Action: {ok:true, message_id}
    else TG send fail
      TG-->>Action: {ok:false}
      Action->>Action: log error, continue (order already saved in DB)
    end
    Action-->>Buyer: redirect /pedidos/enviar/confirmacion?id=1042
    TG-->>Buyer: no direct contact (Shirley reads channel -> WhatsApp)
  end

⚡ 2. Sequence Diagram · Shirley's Bot (Claude Agent SDK via LiteLLM → Groq)

End-to-end execution for Shirley's message: "set the moon necklace stock to 3".

sequenceDiagram
  autonumber
  actor Shirley as 👑 Shirley (Telegram)
  participant TG as Telegram Bot API
  participant WH as POST /telegram/webhook (Next.js)
  participant SDK as Claude Agent SDK (query + tools)
  participant Lite as LiteLLM Proxy :4000 (self-hosted)
  participant Groq as Groq API Cloud (llama-3.3-70b free)
  participant DB as PostgreSQL (Payload Local API)

  Shirley->>TG: "set the moon necklace stock to 3"
  TG->>WH: POST /telegram/webhook {update_id, chat_id, text}
  WH->>WH: verify secret -> check chat_id==ADMIN? -> dedup update_id
  alt not Shirley
    WH-->>TG: 200 OK (ignored)
  else is Shirley
    WH->>SDK: runShirleyAgent(text, {payload, chatId})
    SDK->>Lite: POST /v1/messages (Anthropic API format)
ANTHROPIC_BASE_URL=http://litellm:4000
tools: [actualizarInventario, buscarProducto...]
    Lite->>Lite: translate Anthropic -> OpenAI (drop_params: true)
    Lite->>Groq: POST /openai/v1/chat/completions {model: llama-3.3, tools}
    Groq-->>Lite: {tool_calls:[{name:actualizarInventario, args:{slug:collar-luna, stock:3}}]}
    Lite-->>SDK: {content:[{type:tool_use, name:actualizarInventario}]}
    SDK->>DB: payload.update({collection:products, where:{slug:collar-luna}, data:{stock:3}})
    DB-->>SDK: {ok:true, stock:3}
    SDK->>Lite: tool_result -> Groq (round 2)
    Lite->>Groq: POST /openai/v1/chat/completions (with result)
    Groq-->>Lite: {content: "Done Shirley, Moon Necklace stock is now 3 💜"}
    Lite-->>SDK: final text
    SDK-->>WH: reply string
    WH->>TG: sendTelegramReply({chatId: Shirley, text: reply})
    TG-->>Shirley: "Done Shirley, Moon Necklace stock is now 3 💜"
  end
