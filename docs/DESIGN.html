Nenúfar: Systems Design Zero-cost commerce, human-closed sales, and resilient agent operations

Project: Nenúfar (Cartagena, Colombia) Engineers: Alejandro Ocampo & Shirley Stack: Payload CMS v3 + Next.js App Router + LiteLLM / Groq Budget: Strict $0/mo
Executive Thesis: Nenúfar replaces expensive payment gateways and brittle SaaS with an embedded monolith and a Telegram-driven human sales closing flow. Customers browse and build carts on the web; Shirley closes payments, sizing, and shipping directly on WhatsApp. The store operates under a strict $0/mo fixed cost invariant, protected by in-process seams, SHA-256 idempotency, and an autonomous operations agent constrained by a 190k daily token circuit breaker.

1. Problem and Goals

Artisan jewelry businesses face prohibitive payment gateway fees (3–5% + fixed fees on Stripe/Wompi), customer checkout friction, and recurring SaaS debt. Customers in Colombia demand personal WhatsApp consultation for custom sizing and trust. Shirley needs operational control directly from Telegram without navigating web admin consoles.

  • ① Strict $0/mo Infrastructure (Art. I): Zero SaaS fees. Compute, storage, and models run 100% on Always-Free tiers (Oracle Cloud VPS / Vercel + PostgreSQL + Groq Free).
  • ② Human-Closed Sales (ADR-001): Web checkout creates Payload order with status processing and dispatches rich HTML to Telegram with a pre-filled WhatsApp link. Shirley coordinates payment and logistics manually.
  • ③ Colombian Localization & Privacy (Art. V/VI): Prices strictly formatted as $ 45.000 (never literal COP). Ley 1581 (habeas data) explicit consent. Validated Colombian mobile numbers.
  • ④ Resilient Agent Operations (ADR-002): Single-admin Telegram bot powered by Claude Agent SDK → LiteLLM (:4000) → Groq (Llama-3.3-70b-versatile) with automatic burst fusion and token caps.

Non-goals: Automated payment gateways; public conversational customer chatbots; microservice networks; paid proprietary LLM APIs.

2. Interface: System Contracts

  • Web Storefront: GET /shop, /products/[slug], /galeria, /eventos.
  • Order Submission: POST /pedidos/enviar (Server Action). Enforces Ley 1581 consent, phone format, stock checks, SHA-256 idempotency → creates Order in Payload → Telegram dispatch → redirect.
  • Shirley Ops Bot: POST /telegram/webhook. Checks x-telegram-bot-api-secret-token, validates admin ID, fuses rapid multi-messages within 1000ms debounce, applies HITL confirmation gates on destructive tools.
  • Calendar Feed: GET /api/calendar/feed. Revalidated every 5 min; subscribable via Google Calendar URL.

4. How We Measure: Evals & Reliability

  • Integration Suites: checkout.int.spec.ts (stock & duplicate prevention), agent-tools.int.spec.ts (tool parity & HITL gates), agent-runtime.int.spec.ts (auth guards & 45s fallback timeout), landing-blocks.int.spec.ts (currency compliance).
  • Token Canary & Budget: DAILY_WARN_TOKENS = 150_000, DAILY_PARK_TOKENS = 190_000. When reached, agent sends one Telegram alert and gracefully parks until 00:00 UTC.
  • Circuit Breaker: 3 consecutive gateway failures trigger a 5-minute pause (CIRCUIT_BREAKER_MS = 300_000).
  • Input Truncation: Max 1,000 chars per message; conversational history limited to 4 messages (2,000 chars).
  • Network Partition Resiliency: Orders persist in PostgreSQL even if Telegram fails (logged with warn=1).
